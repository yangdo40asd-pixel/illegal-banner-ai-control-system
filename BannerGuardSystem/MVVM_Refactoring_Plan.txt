====================================================================
           BannerGuardSystem MVVM 리팩터링 상세 계획서
====================================================================

이 문서는 기존 God Object(MainViewModel) 형태의 아키텍처를 
엄격한 MVVM(Model-View-ViewModel) 패턴으로 전환하기 위한 
단계별/가지형(Tree) 형태의 상세 실행 계획입니다.
각 단계는 [실행 -> 안정성 검증 및 테스트]의 점진적 스프린트로 진행됩니다.

====================================================================

1. DI(Dependency Injection) 및 Bootstrapper 구축
   |
   |-- 1.1. 의존성 패키지 설치
   |    |-- Microsoft.Extensions.DependencyInjection NuGet 패키지 추가 (완료)
   |
   |-- 1.2. AppBootstrapper.cs 생성 (완료)
   |    |-- ServiceCollection 초기화
   |    |-- 뷰모델(ViewModels) 등록 (ShellViewModel, MainViewModel 등)
   |    |-- 서비스(Services) 등록을 위한 플레이스홀더 구성
   |
   |-- 1.3. App.xaml.cs 진입점 수정 (완료)
   |    |-- AppBootstrapper.Build() 호출
   |    |-- MainWindow의 DataContext에 DI 컨테이너로부터 가져온 ShellViewModel 주입
   |
   |-- 1.4. [필수] 안정성 검증 및 테스트
   |    |-- 앱 정상 부팅 및 UI 최초 표시 여부 확인
   |    |-- DI 컨테이너 예외(Service Not Found) 발생 여부 체크

2. ShellViewModel (전역 프레임) 도입
   |
   |-- 2.1. ShellViewModel.cs 생성
   |    |-- BaseViewModel (INotifyPropertyChanged) 상속
   |    |-- 프로퍼티 구현: CurrentView, IsConnected, SystemModeText, CpuUsageText 등 전역 상태
   |    |-- 커맨드 구현: NavigateCommand 등
   |
   |-- 2.2. MainViewModel 의존성 분리
   |    |-- MainViewModel에 섞여 있던 '전역 상태(Global State)' 변수들 추출
   |    |-- 메인 윈도우 UI와 1:1 매칭되도록 ShellViewModel로 로직 이관
   |
   |-- 2.3. MainWindow.xaml 바인딩 수정
   |    |-- 전역 상태 표시줄(Top Status Bar)을 ShellViewModel에 맞게 바인딩 검증
   |
   |-- 2.4. [필수] 안정성 검증 및 테스트
   |    |-- 앱 실행 후 상단 상태 표시줄 값(CPU, RAM, 연결 상태)이 정상 갱신되는지 확인
   |    |-- 기존 MainViewModel에서 추출한 로직으로 인한 사이드 이펙트 모니터링

3. NavigationService (네비게이션/라우팅) 구현
   |
   |-- 3.1. 인터페이스 정의 (INavigationService)
   |    |-- void Navigate(string viewKey);
   |    |-- void GoBack(); (필요시)
   |
   |-- 3.2. 구현체 작성 (NavigationService.cs)
   |    |-- ViewType과 ViewModelType을 매핑하는 Dictionary 유지
   |    |-- DI 컨테이너(IServiceProvider)를 통해 View와 ViewModel 인스턴스화
   |    |-- View.DataContext = ViewModel 주입 후 ShellViewModel.CurrentView 갱신
   |
   |-- 3.3. AppBootstrapper 연동
   |    |-- services.AddSingleton<INavigationService, NavigationService>();
   |    |-- 네비게이션 딕셔너리에 키값 매핑 (예: "RealTimeMonitoring" -> RealTimeMonitoringView)
   |
   |-- 3.4. [필수] 안정성 검증 및 테스트
   |    |-- 좌측 사이드 메뉴 버튼 클릭 시 화면(CurrentView) 정상 전환 테스트
   |    |-- 네비게이션 동작 중 메모리 누수 및 화면 로드 지연 검사

4. 화면별 전용 ViewModel 분할 (God Object 해체)
   |
   |-- 4.1. RealTimeMonitoringViewModel 생성
   |    |-- AI 분석 수신, YOLO 박스 처리, AlertFeed 목록 관리 로직 이관
   |    |-- IWebSocketService, IAlertRepository 주입받도록 구성
   |
   |-- 4.2. CctvMonitoringViewModel 생성
   |    |-- 채널 목록(Channels) 관리, 지도 연동, 선택 채널 변경 로직 이관
   |
   |-- 4.3. 기존 ViewModel 의존성 정리
   |    |-- EnforcementStatusViewModel: IDatabaseService 주입으로 리팩터링
   |    |-- SystemSettingsViewModel: 종속성 직접 생성(new) 제거
   |    |-- StatisticsReportViewModel: 필요 서비스 주입형태로 변경
   |
   |-- 4.4. [필수] 안정성 검증 및 테스트
   |    |-- VLM 검증 메뉴 진입 시 실시간 바운딩 박스가 제대로 뜨는지 테스트
   |    |-- 화면 이동 후 이전 화면으로 돌아왔을 때 상태가 보존되거나 초기화되는지 검증

5. Model 내 UI 종속성(강결합) 제거
   |
   |-- 5.1. DTO 클래스 정리
   |    |-- BannerDetectionEventDto, BannerAlert 등에서 System.Windows.Media.SolidColorBrush 제거
   |    |-- 상태값을 나타내는 Enum 또는 단순 string/int 프로퍼티로 대체
   |
   |-- 5.2. IValueConverter 작성
   |    |-- AlertLevelToBrushConverter.cs: 긴급/일반 상태값을 UI 색상 코드로 변환
   |    |-- StatusToBrushConverter.cs: 처리 상태를 색상으로 변환
   |
   |-- 5.3. XAML 리소스 딕셔너리 적용
   |    |-- App.xaml 또는 Window.Resources에 Converter 등록
   |    |-- 뷰 파일들의 Foreground/Background 바인딩에 Converter 적용
   |
   |-- 5.4. [필수] 안정성 검증 및 테스트
   |    |-- UI의 알림 레벨(긴급/일반) 색상이 변경 전과 동일하게 렌더링되는지 확인
   |    |-- Converter 동작 중 Null 참조 예외 방지 테스트

6. 서비스 계층 추상화 및 Dialog 분리
   |
   |-- 6.1. 비즈니스 서비스 추상화
   |    |-- 공용 데이터(AlertFeed)를 보관할 'IAlertRepository' 싱글톤 서비스 구축
   |    |-- 지도 연동 및 HTML 렌더링 로직을 'IMapService'로 분리
   |
   |-- 6.2. IDialogService 도입
   |    |-- MessageBox.Show()가 ViewModel에 하드코딩된 부분 탐색
   |    |-- Task ShowMessageAsync(string title, string msg) 형태의 인터페이스 정의
   |    |-- ViewModel 테스트 가능성을 위해 UI 호출을 서비스로 위임
   |
   |-- 6.3. [필수] 안정성 검증 및 테스트
   |    |-- 데이터베이스 삭제/저장 시 알림 팝업창이 비동기로 정상 출력되는지 확인
   |    |-- 공용 데이터 저장소(AlertRepository) 변경 시 타 뷰모델에서 즉각 갱신되는지 테스트

7. 코드-비하인드(Code-Behind) 최소화
   |
   |-- 7.1. RealTimeMonitoringView.xaml.cs 정리
   |    |-- PropertyChanged 이벤트 직접 구독 방식 제거 -> 바인딩으로 교체
   |    |-- WebView2(지도) 직접 조작 로직을 ViewModel의 바인딩 속성 변화로 트리거하도록 수정
   |
   |-- 7.2. 기타 뷰 로직 정리
   |    |-- Click 이벤트 대신 ICommand(RelayCommand) 사용 강제 확인
   |    |-- 다이얼로그 닫기 등의 View 고유 동작은 Interaction.Triggers 또는 Attached Property 사용 검토
   |
   |-- 7.3. [필수] 안정성 검증 및 테스트
   |    |-- XAML과 Code-Behind 결합 해제 후에도 기존 UI 인터랙션(클릭, 스크롤, 줌 등)이 동작하는지 수동 검증

   |
   |-- 8.2. 시스템 전반 통합 테스트
   |    |-- AI 서버와 연결하여 장시간 수신 시 메모리 누수 확인
   |    |-- 전체 화면 사이클 전환하며 DI/라우팅 상태 점검
