# 현재 문제점과 수정 방향

최종 검토: 2026-11-18. 현재 소스와 이번 실행 결과를 기준으로 작성했다.

## 1. 모델 초기화 실패의 상태 전달 부족 — 후속 개선

**문제점:** `app/core/ai_runtime.py`는 초기화 예외 때 loading을 해제하지만 오류 내용을 별도 상태로 보관하지 않는다. `wait_for_ai_service()`는 ready 이벤트만 기다리므로 초기화 실패 후 연결된 분석 작업이 계속 기다릴 수 있다. `/health`의 online만으로 실패 원인을 알기 어렵다. 이는 소스에서 확인한 실패 경로이며 정상 GPU 시험에서 발생한 오류는 아니다.

**수정 방향성:** ready/loading/error를 명시한 수명주기 상태를 만들고 초기화 예외 메시지와 시각을 보관한다. 대기 함수에 실패 통지와 제한 시간을 추가하고 `/health` 및 WPF 상태바에 모델 실패를 전달한다. 파일 없음·메모리 부족을 모의 주입해 대기 종료, 재시도, 정상 복구를 확인한다. 재시도가 동시에 모델을 중복 생성하지 않게 기존 lock을 유지한다.

관련 파일: `src/backend/app/core/ai_runtime.py`, `src/backend/app/main.py`, `src/desktop/BannerGuardSystem/Services/Monitoring/SystemMonitorService.cs`.

## 2. 기존 그래픽 패키지 호환성 경고 — 유지 중

**문제점:** OpenTK 3.3.1, OpenTK.GLWpfControl 3.3.0, SkiaSharp.Views.WPF 3.116.1에 NU1701 경고가 남는다. 현재 빌드와 화면 실행은 통과했지만 모든 그래픽 조합의 호환성을 보장하지 않는다. Python API 시험에는 Starlette/httpx 및 anyio 사용 중단 예정 경고 2개가 있다.

**수정 방향성:** 그래픽 패키지의 유입 경로를 확인하고 관련 차트·WPF 패키지를 함께 호환되는 조합으로 시험한다. 현재 버전을 보존한 별도 변경에서 차트, WebView, 영상 오버레이를 확인한 후 전환한다. Python 시험 의존성 조정도 별도 변경으로 검증한다. 이번 폴더 리팩토링에서 일괄 업그레이드하지 않았다.

## 3. 신규 PC 설치와 독립 설치 프로그램 — 미검증 범위

**문제점:** 현재 환경에서 잠근 의존성과 로컬 실행 폴더는 검증했지만, 새 Windows에서 처음부터 설치하거나 Python까지 내장한 설치 프로그램을 검증하지 않았다. 원격 CI도 아직 실행하지 않았다.

**수정 방향성:** 새 환경에서 `setup.ps1` → CPU 시험 → 모델 다운로드 → GPU 분석 → 앱 종료 순서로 재현하고 설치 로그를 남긴다. 현재 배포본에는 .NET 9 Desktop Runtime, 준비된 Python 3.13 AI 환경, 모델 캐시 또는 다운로드가 필요하다. 내장형 배포가 필요하면 별도 패키징 방식을 정하고 개발 폴더가 없는 PC에서 확인한다.

## 4. 정량 평가·공개 권리·개인 기여 — 제출 전 확인

**문제점:** YOLO 학습 CSV 지표와 실제 단일 이미지 추론 성공이 전체 불법 판정 정확도를 증명하지는 않는다. 현재 CCTV는 로컬 영상 데모이며, 모든 버튼의 수동 회귀 시험과 VLM 정답셋 평가는 완료하지 않았다. 실제 학교 평가표, 개인 기여, 프로젝트 자체 라이선스는 소유자가 확인해야 한다.

**수정 방향성:** 독립된 정답셋에 표본 수·오류 유형·처리 지연을 기록한다. 실제 영상·원천 데이터의 공개 가능 여부를 확인하고 기본 공개 입력은 합성 샘플을 사용한다. 담당 범위와 협업·도구 사용을 확인해 기여 문서를 확정한다. 현재 수치를 확대 해석하지 않는다.

## 이번에 수정하고 확인한 항목

|---|---|---|
| 특정 D: 경로 및 옛 폴더 구조 의존 | C#/Python 공통 경로 설정, 루트 표식, 환경변수 우선순위 | 다른 공백·한글 경로와 다른 작업 폴더에서 양 언어 경로 일치·HTTP·WS 통과 |

| 탐지값이 없는데 95.2%로 표시 | 미탐지는 미탐지, 탐지 결과는 실제 confidence 표시 | MSTest 확인 |
| CCTV 채널 수 24개 고정 표시 | 현재 Channels.Count를 표시 | 4채널 구성 및 바인딩 확인 |
| 배포본에 예전 DB 복사 | 프로젝트 DB 복사 설정 제거, 원본 보관, 패키지 검사 추가 | 새 배포본에 DB·개인 설정·private 폴더 없음 |
| 소스 아래에 과거 분석 이미지 캐시 잔존 | runtime 보관, 배포 시 Python 파일만 복사, 배포 포스터는 합성 이미지로 교체 | 캐시 이미지 제외 및 포스터 해시 검사 |
| DB·가중치 이동 중 유실 위험 | SQLite 온라인 백업·공유 migration·가중치 해시 | 5개 테이블 보존, integrity_check=ok, SHA-256 일치 |
| 문서에서 과거 FAIL과 현재 상태 혼재 | 과거 기록 보관, 역할별 현행 문서와 결과 구분 | 문서 색인·링크 검사 |

GPU 0%는 유휴 시 정상일 수 있다. 이번 검증에서는 YOLO 결과 텐서의 CUDA 장치와 실제 VLM 완료를 따로 확인했다. 수신 대기 상태도 서버 연결, 모델 준비, 분석 요청, 결과 수신을 나눠 판단해야 한다.
