■ 0. 한 줄 요약
--------------------------------------------------------------------------------
VLM 검증 화면은 "사람이 최종 판단하는 검토 데스크"이다.
CCTV 모니터링이 LIVE 영상+YOLO 다중 박스라면,
VLM 검증은 "분석 프레임 스냅샷 + YOLO 박스 1개 + VLM(Qwen) 텍스트 + 승인/기각"이다.

데이터는 WebSocket channel_batch → MainViewModel.AlertFeed / ActiveAlert 로 들어온다.
화면은 MainViewModel 하나를 DataContext로 공유한다 (별도 ViewModel 없음).

■ 3. ViewModel 상태 (MainViewModel.cs)
--------------------------------------------------------------------------------

[VLM 화면이 직접 쓰는 프로퍼티]

  AlertFeed          ObservableCollection<BannerDetectionEventDto>
                     좌측 목록. WebSocket 수신 시 ProcessAlertForFeed()로 insert/update

  ActiveAlert        BannerDetectionEventDto?
                     하단 상세 패널의 "현재 검토 중인 1건"
                     set 시:
                       - HasActiveAlert / HasNoActiveAlert 갱신
                       - LoadPastViolationsForActiveAlert() → HistoryLog 채움
                       - ActiveAlert.CctvId 와 일치하는 Channels 항목 → SelectedChannel 설정
                       - MapQuery = SelectedChannel.Address → 지도 갱신

  SelectedChannel    CctvChannel?
                     스냅샷 라벨용 ChannelId 표시. VLM 화면에서 MP4 재생은 안 함

  HasActiveAlert     ActiveAlert != null
  HasNoActiveAlert   ActiveAlert == null

  MapQuery           string — 지도 검색어

  TodayDetectionCount / PendingCount / CompletedCount / EmergencyCount
                     KPI 카드용 카운터

  ApproveCommand / DismissCommand / SelectAlertCommand
                     하단 버튼 & 목록 "검토"

[정의돼 있으나 VLM XAML에 바인딩 없는 것]

  HistoryLog         EnforcementHistoryDto 컬렉션 — ActiveAlert 바뀔 때 DB에서 로드하나 UI 미표시
  ActiveAlert.VerdictColor / VerdictIcon / StatusCode / VerdictColorLegend
                     DTO에 구현됨. VLM 화면 박스/뱃지에 미연결
  ActiveAlert.Stage / StageText / BoundingBoxLabelText
                     Tier 2/3 라벨 — VLM 화면 미사용


■ 4. 데이터 모델 — BannerDetectionEventDto
--------------------------------------------------------------------------------

WebSocket JSON ↔ C# DTO 1:1 (PascalCase)

  [식별]
  Id, CctvId, LocationAddress, Timestamp, TimestampOffset

  [Tier 1 — YOLO]
  HasBanner, BoundingBox (X,Y,Width,Height), Confidence
  FullImageBase64     — 전체 프레임 (VLM 스냅샷 배경)
  YoloDetectionLabelText — "현수막 (Banner) - xx% | Tier 1: 탐지" (CCTV 박스 라벨용)

  [Tier 2 — OCR]
  OcrText, OcrConfidence

  [Tier 3 — VLM]
  IsVlmTriggered, VlmAnalysis, StatusCode
  StatusCode 예: LEGAL_PUBLIC, LEGAL_COMMERCIAL, LEGAL_POLITICS,
                ILLEGAL_COMMERCIAL, ILLEGAL_CONTENT, MANUAL_REVIEW, EXEMPT_ELECTION

  [이미지]
  CroppedImageBase64  — 현수막 크롭 (목록 썸네일, VLM 패널 소형 이미지)
  CropImageUri        — http://localhost:8000/assets/... (백엔드 static)

  [기타]
  IsRepeatOffender, RepeatCount → 목록 긴급 스타일 (빨간 테두리)

  [UI 헬퍼 — VLM에서 써야 할 것들]
  VerdictColor        StatusCode → SolidColorBrush (합법=초록, 불법=빨강 등)
  VerdictColorLegend  한글 범례 문자열
  VerdictIcon         이모지+한글 판정 요약
  AiReason            VlmAnalysis 우선, 없으면 기본 문구


■ 5. 백엔드 → WPF 데이터 파이프라인 (현재)
--------------------------------------------------------------------------------

[시뮬레이터] backend/app/api/websocket_endpoints.py
  5초 주기
  채널별 MP4 첫 프레임 → temp jpg → AI 추론
  채널당 channel_batch 1건 WebSocket 전송

[메시지 형식] ChannelDetectionBatch
  MessageType: "channel_batch"
  CctvId, FrameWidth, FrameHeight (1920×1080)
  Detections: BannerDetectionEvent[]  (현수막 1개당 1 이벤트)

[AI 파이프라인] ai_inference_service.py (탐지 1건당)
  1. YOLO → bbox
  2. DB IoU 0.4 매칭 (캐시된 VLM 결과 재사용 가능)
  3. VLM(Qwen2.5-VL) 대부분 실행
  4. StatusCode / VlmAnalysis / OcrText 결정
  5. FullImageBase64, CroppedImageBase64 base64 인코딩
  6. BannerDetectionEvent 생성

[WPF 수신] WebSocketService.cs
  MessageType == "channel_batch" → OnChannelBatchReceived

[MainViewModel.OnChannelBatchReceived]
  1. channel.ApplyDetectionBatch(batch)  → CCTV용 CurrentAlerts (VLM 화면과 별개)
  2. foreach detection → ProcessAlertForFeed(d, fromSameBatch:true) → AlertFeed
  3. ActiveAlert = IsVlmTriggered 우선 else Detections[0]
     ※ 배치마다 ActiveAlert가 덮어써짐. 사용자가 "검토"로 고른 항목도 다음 배치에 밀릴 수 있음

[ProcessAlertForFeed 쓰로틀]
  동일 CctvId 3초 이내 중복 insert 방지
  fromSameBatch=true 이면 쓰로틀 무시 (같은 채널 다중 현수막 Feed 등록 가능)


■ 6. CCTV 화면 vs VLM 화면 — 반드시 지켜야 할 분리
--------------------------------------------------------------------------------

  ┌─────────────────┬──────────────────────────┬────────────────────────────┐
  │                 │ CCTV (CctvMonitoringView)│ VLM (RealTimeMonitoringView)│
  ├─────────────────┼──────────────────────────┼────────────────────────────┤
  │ 영상            │ MP4 LIVE 재생            │ 없음 — FullImageBase64 스냅샷│
  │ 박스 개수       │ N개 (CurrentAlerts)      │ 1개 (ActiveAlert)          │
  │ 박스 색         │ 고정 빨강 #FF4757        │ 고정 빨강 (YOLO 전용)      │
  │ VLM 판정 색     │ 사용 금지                │ StatusCode/VerdictColor 사용│
  │ 좌표 기준       │ OverlayFrame 1920×1080   │ FullImageBase64 해상도     │
  │ 오버레이 모드   │ OverlayOnly=true         │ OverlayOnly=false (프레임+박스)│
  │ 데이터 소스     │ CctvChannel.CurrentAlerts│ MainViewModel.ActiveAlert  │
  └─────────────────┴──────────────────────────┴────────────────────────────┘

다음 작업에서 CCTV 쪽 수정을 VLM에 끌어오거나,
VLM VerdictColor를 CCTV 박스에 섞지 말 것 (이전 사용자 요구사항).


■ 7. YoloBBoxOverlay — VLM 모드 동작
--------------------------------------------------------------------------------

VLM 스냅샷 패널 설정:
  OverlayOnly = false (기본)
  Alert = ActiveAlert (단일)
  FrameSource = ActiveAlert.FullImageBase64
  IsActive = HasActiveAlert

RenderWithFrame() 경로:
  1. FrameSource 또는 FullImageBase64 디코드 → 배경 Image (Opacity=FrameOpacity)
  2. NativeCanvas 원본 해상도에 bbox 1개 (빨간 박스 + Tier1 라벨 + ObjectId)
  3. Viewbox Stretch=Uniform 로 컨테이너에 맞춤

※ MP4 프레임 기준 추론 후에는 FullImageBase64가 1920×1080 JPEG
※ OverlayOnly=true 경로는 VLM에서 사용하지 않음


■ 8. 이미지 로딩 경로
--------------------------------------------------------------------------------

[ImageLoaderConverter]
  - data:image/...;base64,... 또는 raw base64 → BitmapImage
  - 로컬 파일 경로 fallback
  - 사용처: 목록 CroppedImageBase64, VLM 패널 CroppedImageBase64

[YoloBBoxOverlay FrameSource]
  - FullImageBase64 직접 디코드 (ImageDimensionHelper)
  - 배경 프레임 + bbox 동시 렌더

이미지 안 뜨는 경우 체크리스트:
  1. WebSocket channel_batch 수신 여부 (로그: Channel batch: CCTV=...)
  2. ActiveAlert null 여부 (HasNoActiveAlert 오버레이가 가리는지)
  3. FullImageBase64 / CroppedImageBase64 빈 문자열 여부
  4. 시뮬레이터 크래시 (Conv.bn 등) — 추론 자체 실패
  5. JSON 역직렬화 실패 (WebSocket-Err Deserialization)


■ 9. 사용자 액션 흐름 (현재 구현)
--------------------------------------------------------------------------------

[목록에서 검토]
  "검토" 클릭 → SelectAlertCommand(parameter=해당 DTO)
  → ActiveAlert = 선택 항목
  → SelectedChannel / MapQuery 자동 갱신

[합법 확인 / 불법 확정] — 둘 다 OnApproveActiveAlert()
  - PDF 보고서 생성 (Reports 폴더)
  - DB status "단속확정"
  - HighlightChannelAlertState(cctvId, false) → CCTV 박스 제거
  - AlertFeed.Remove(ActiveAlert)
  - SelectNextPendingAlert() → Feed 첫 항목을 ActiveAlert로
  - GC 트리거

[재검토 요청] — OnDismissActiveAlert()
  - DB "오탐기각"
  - 위와 동일하게 Feed/CCTV 정리

※ 합법/불법 버튼이 같은 Command → 다음 작업에서 반드시 분리 필요
※ 승인 시 StatusCode/판정 결과를 DB에 구분 저장하는 로직 없음
