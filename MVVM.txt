1. MVVM이란? (작업 AI가 먼저 이해할 정의)
================================================================================

MVVM = Model · View · ViewModel 세 레이어로 UI와 로직을 나누는 WPF 패턴.

  [View]        화면만. XAML + 최소 code-behind.
                사용자 입력은 Binding/Command로 ViewModel에 전달.
                비즈니스 로직·DB·네트워크 코드 금지.

  [ViewModel]   화면에 보여줄 상태(Property) + 사용자 동작(Command).
                View를 직접 참조하지 않음 (Window, Button 타입 사용 금지).
                Model·Service를 조합해 View용 데이터 제공.
                INotifyPropertyChanged + ObservableCollection + ICommand 필수.

  [Model]       데이터·도메인 규칙. UI(WPF) 타입 의존 금지.
                Brush, Color, Visibility 등 WPF 네임스페이스 넣지 말 것.

  [Service]     MVVM 밖 계층. WebSocket, DB, PDF, 백엔드 기동 등.
                ViewModel이 인터페이스로 주입받아 사용 (DI 권장).

핵심 원칙 4가지:
  ① View는 ViewModel만 안다 (DataContext Binding)
  ② ViewModel은 View를 모른다
  ③ View code-behind는 얇게 (입력 라우팅·순수 View 로직만)
  ④ Model은 UI 독립

  판단 기준: Models/ 폴더에 using System.Windows.* 가 없어야 함.


─── 4-2. ViewModel 수정 규칙 ───

  MainViewModel 역할 축소:
    · 자식 ViewModel 프로퍼티만 노출:
        public DashboardViewModel Dashboard { get; }
        public CctvMonitorViewModel Monitor { get; }
        public AlertFeedViewModel Feed { get; }
    · WebSocket OnAlertReceived는 MainViewModel이 받아 자식 VM에 분배
    · 텔레메트리는 TelemetryViewModel로 분리

  각 ViewModel:
    · public 속성 + OnPropertyChanged
    · public ICommand 속성
    · async 작업은 async/await, UI 갱신은 RunOnUi 또는 Dispatcher
    · 절대 new MainWindow(), MessageBox 직접 호출 지양 (IDialogService 도입 선택)

  Command UI 연결 필수:
    · ApproveCommand  → XAML Button "단속 확정"
    · DismissCommand  → XAML Button "오탐 기각"
    · ToggleRoiModeCommand → XAML ToggleButton "ROI 모드"
    · SelectChannelCommand → 이미 RadioButton 연결됨 (유지)

  생성자 DI (최소 인터페이스):
    public MainViewModel(
        IWebSocketService ws,
        IDatabaseService db,
        IPdfReportService pdf)
    App.xaml.cs에서 구현체 주입.


─── 4-3. View 수정 규칙 ───

  MainWindow.xaml:
    · 큰 덩어리를 UserControl로 분리 권장
    · 피그마 시안 반영 시 Binding 경로만 깨지 않게 주의
    · 버튼은 Click 이벤트 금지 → Command Binding

  MainWindow.xaml.cs:
    · InitializeComponent() + (선택) InputBindings 만
    · KeyDown 핸들러 → 아래 XAML로 이전:
        <Window.InputBindings>
          <KeyBinding Key="Space" Command="{Binding Dashboard.ApproveCommand}"/>
          <KeyBinding Key="Escape" Command="{Binding Dashboard.DismissCommand}"/>
        </Window.InputBindings>

  CctvChannelControl.xaml.cs 리팩터링 (중요):
    [현재 문제] UpdateBoundingBox(), ROI Mouse 이벤트가 code-behind에 240줄

    [목표]
    · 순수 View 로직만 code-behind: Canvas 좌표 계산, Draw 호출
    · 상태(CurrentAlert, Status)는 Binding으로 UserControl DataContext = CctvChannel VM
    · 또는 Attached Behavior / IBoundingBoxRenderer 서비스로 분리
    · ROI 완료 좌표는 ViewModel 프로퍼티 ObservableCollection<RoiRect>에 추가

    최소 목표(1차): ViewModel에서 Alert/Channel 상태만 Binding, 그리기는 code-behind 유지하되
                    비즈니스 판단 로직은 ViewModel로 이전.

6. 피그마 UI 반영 시 MVVM 체크리스트
================================================================================

  새 UI 요소 추가할 때마다:
  □ 버튼 → Command Binding 있는가? (Click= 금지)
  □ 텍스트/숫자 → ViewModel Property Binding 있는가?
  □ 목록 → ObservableCollection + ItemsSource 있는가?
  □ 이미지 → Converter 또는 ViewModel Uri/Base64 Property 있는가?
  □ 색/아이콘 → Model 문자열 코드 + Converter 있는가?
  □ code-behind에 DB/네트워크/판단 로직 들어가지 않았는가?

8. 발표·시험용 한 줄 (리팩터링 후 이렇게 말할 수 있어야 함)
================================================================================

  "View(XAML)는 Binding만 담당하고, 상태와 동작은 ViewModel의 Property·Command가
   제공하며, Model은 WPF와 무관한 순수 데이터입니다. WebSocket·DB·PDF는
   Service 레이어로 분리했고, ViewModel은 Service 인터페이스만 의존합니다."
