📋 문제 진단 및 해결 결과 보고서
WPF 클라이언트와 AI 백엔드 연동 과정에서 발생했던 핵심 오작동 원인과 이를 해결한 구체적인 방안을 요약 보고합니다.

1. [문제 현상] 어떤 문제가 있었나요?
GPU(CUDA) 인식 실패 및 극심한 지연 (흰 배경 멈춤의 원인)
파이썬 단독 실행 시에는 GPU가 잘 작동했으나, WPF 앱 내에서 백엔드가 자동 기동될 때만 GPU를 인식하지 못하고 CPU 모드로 강제 폴백되었습니다.
이로 인해 VLM(Qwen2.5-VL) 추론 시 이미지 한 장당 80초 이상 소요되어, 사용자가 보기에는 화면이 흰색인 채로 응답이 없는 것처럼 느껴졌습니다.
WPF와 백엔드의 통신 먹통 (독립 구동 현상)
WPF 앱을 끄고 다시 켤 때, 이전에 실행되었던 파이썬 백엔드가 백그라운드에 좀비 프로세스로 남아 8000포트를 계속 점유했습니다.
새로 켜진 WPF는 포트 충돌로 인해 백엔드와 연결되지 않아 단속 데이터가 화면에 전혀 들어오지 못하는 문제가 발생했습니다.
2. [원인 분석] 왜 발생했나요?
Windows 환경 변수(PATH) 누락:
C# Process.Start로 python.exe를 실행할 때, 아나콘다(Conda) 환경이 활성화되지 않은 상태로 실행됩니다.
이로 인해 CUDA 가속에 필요한 핵심 DLL 파일들이 들어있는 Conda 하위 폴더들(Library/bin 등)이 프로세스 PATH에 포함되지 못해 PyTorch가 GPU 로드에 실패한 것입니다.
좀비 프로세스 생존:
강제 종료나 통신 단절 시 Job Object 커널 객체가 포트를 잡고 있는 자식 프로세스를 안정적으로 100% 격추하지 못해 발생했습니다.
3. [해결 방안] 어떻게 해결했나요?
우리는 
BackendManager.cs
 코드를 개편하여 이를 완벽하게 자동화했습니다.

Conda 환경 변수 동적 주입을 통한 GPU 활성화
WPF가 파이썬을 기동할 때, 사용 중인 파이썬 인터프리터 경로를 기준으로 Conda의 핵심 DLL 검색 경로들을 조합하여 프로세스 PATH 환경 변수에 강제로 추가해 주었습니다.
결과: WPF에서 자동 실행된 백엔드에서도 CUDA GPU 가속이 100% 활성화되었으며, VLM 추론 속도가 기존 80초에서 약 14초 수준으로 80% 이상 크게 단축되었습니다.
포트 자동 정리(KillProcessOnPort) 로직 도입
백엔드를 구동하기 직전에 netstat을 실행하여 포트 8000을 점유하고 있는 기존 좀비 프로세스의 PID를 탐색하고, 발견 시 즉시 강제 종료(Kill)하도록 코드를 추가했습니다.
결과: 프로그램 재실행 시 무조건 포트 점유 충돌 없이 깨끗한 상태에서 백엔드를 100% 새로 가동하고 즉각 웹소켓을 연결시킵니다.
