2. 프로그램 켜지는 순서 (타임라인)
================================================================================

  [1] 사용자가 BannerGuardSystem.exe 실행 (또는 run.bat)

  [2] App.OnStartup (BannerGuardSystem/App.xaml.cs)
        ├─ BackendManager.Start()          ← Python AI 서버 기동 (가장 먼저!)
        ├─ QuestPDF 라이선스
        ├─ LibVLC.Core.Initialize()        ← CCTV용 (AI GPU와 별개)
        ├─ new MainViewModel()
        ├─ MainWindow.DataContext = VM
        └─ mainWindow.Show()

  [3] BackendManager.Start() (BannerGuardSystem/Services/BackendManager.cs)
        ├─ 포트 8000 점유 프로세스 정리 (netstat + kill)
        ├─ (우선) ai_server.exe 있으면 배포 모드로 실행
        ├─ (없으면) backend/app/main.py 찾아서 python -u 로 실행
        │     · exe 폴더에서 최대 10단계 상위로 올라가며 main.py 탐색
        │     · WorkingDirectory = 프로젝트 루트 (D:\138.종합 민원 이미지 AI데이터)
        │     · Conda PATH를 환경변수에 주입 (CUDA DLL 로드용)
        ├─ Job Object 등록 (WPF 종료 시 Python도 같이 죽게)
        └─ 로그 → exe옆 backend_manager.log

  [4] Python main.py 기동
        ├─ uvicorn 포트 8000
        ├─ lifespan: AIInferenceService 싱글톤 로드 (YOLO + Qwen, 수 분 소요 가능)
        └─ /ws/alerts WebSocket 대기

  [5] MainViewModel 생성자
        ├─ DatabaseService.Initialize()      ← WPF용 SQLite
        ├─ WebSocketService.ConnectAsync("ws://localhost:8000/ws/alerts")
        ├─ CCTV 채널 4개 로드 + LibVLC Play()
        └─ 텔레메트리 타이머 시작

  [6] WebSocket 연결 성공 시
        ├─ 서버: run_real_ai_simulator() 백그라운드 태스크 시작
        │     · 3초(첫) / 8초마다 Assets JPG 한 장씩 AI 분석
        │     · 결과 JSON을 WebSocket으로 push
        └─ WPF: OnAlertReceived → AlertFeed에 추가 → UI 자동 갱신

  [7] App.OnExit
        ├─ BackendManager.Stop()
        └─ LibVLC Dispose()

4. GPU / CUDA — 누가 뭘 쓰는지 (분리해서 이해)
================================================================================

  [WPF 쪽 — BannerGuardSystem]
  · LibVLC + VideoLAN.LibVLC.Windows
    - CCTV RTSP/파일 영상 재생
    - UI에 "LibVLC DXVA2 가속" 표시 (하드웨어 디코드)
    - ★ YOLO/Qwen AI 연산과 무관

  [Python 쪽 — backend/app/services/ai_inference_service.py]
  · torch.cuda.is_available() → True면 device="cuda"
  · YOLO (ultralytics): self.yolo(img, device=self.device)
  · Qwen2.5-VL-3B-Instruct:
      - CUDA 있으면: 4bit 양자화 (BitsAndBytesConfig) + device_map="auto"
      - CUDA 없으면: CPU float32 (매우 느림, 실사용 비권장)
  · HuggingFace에서 Qwen 모델 최초 다운로드 (~6GB, 인터넷 필요)
    - 캐시: 사용자 홈 .cache/huggingface/ (또는 florence2_cache 폴더 참고)

  [VRAM 대략적 사용 — RTX 3080 10GB 기준 설계]
  · YOLO best.pt: ~2GB 내외
  · Qwen 4bit: ~3.5GB 내외
  · 동시에 한 프로세스(Python 서버)에서만 GPU 점유

  ★ EasyOCR 주의
  · 코드 주석/로그에는 "YOLO+EasyOCR+Qwen"이라 적혀 있으나
  · 현재 ai_inference_service.py 에서 EasyOCR 실제 로드/호출 없음
  · OCR+판정은 Qwen VLM이 담당 (Tier 2 UI 라벨은 역사적 이름)

  ★ Base64 이미지가 크므로 WebSocket 버퍼 64KB (WebSocketService.cs)

10. 연결이 어려웠던 이유 (과거 트러블 포인트 정리)
================================================================================

  ① 프로젝트 경로 하드코딩
     D:\138.종합 민원 이미지 AI데이터 가 여러 파일에 박혀 있음.
     경로만 바꿔도 YOLO·DB·시뮬레이터 이미지 전부 실패.

  ② WPF가 Python을 "찾는" 방식이 복잡
     · publish/bin 깊은 폴더에서 실행해도 main.py를 상위 탐색
     · Python은 conda banner_env → anaconda3 → PATH 순 탐색
     · CUDA DLL 위해 Conda Library\bin 을 PATH에 수동 주입

  ③ 서버 기동 ↔ WebSocket 연결 타이밍
     · AI 모델 로딩(YOLO+Qwen)이 끝나기 전에 WPF가 ws 연결 시도 가능
     · WebSocketService는 재연결(backoff) 있어서 대부분 복구됨
     · 첫 연결 실패 시 1~30초 후 자동 재시도

  ④ GPU/환경 의존
     · torch CUDA 버전 ≠ NVIDIA 드라이버 → cpu 폴백 또는 크래시
     · Qwen 첫 다운로드 중 네트워크 끊기면 서버 lifespan 실패

  ⑤ WPF 영상(LibVLC) ≠ AI 분석 이미지
     · 화면 CCTV는 RTSP/placeholder
     · AI는 Assets JPG 시뮬레이터
     · "영상에서 탐지된 박스"와 "서버 분석 결과"가 완전 동기는 아님

  ⑥ JSON 필드 불일치 시
     · Python schema ↔ C# DTO 필드명 달라지면 UI 빈 화면
     · BoundingBox vs BBox 구조 주의

12. 수동 테스트 방법 (연결 확인 체크리스트)
================================================================================

  □ 1. run.bat 또는 exe 실행
